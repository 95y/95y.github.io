TypeScript never 排查：类型为什么被收窄到不可能

发表于2025-08-15|更新于2025-08-15|前端排障

先说结论：不要从报错文字直接猜答案。把现场压缩成最小例子，再顺着引用、网络或渲染链路往回找，通常更稳。

属性访问报 Property does not exist on type never；空数组推导为 never[]，后续无法 push；穷尽分支中的变量类型突然变成 never。

给空数组补上元素类型

拆开表达式观察每一步推导

  1. 把复杂表达式拆成中间变量查看每一步推导类型
  2. 检查泛型参数、空数组和 useState 的初始类型
  3. 用 assertNever 确认是真正穷尽还是上游类型写错
  • 初始化信息不足导致泛型或数组元素无法推导
  • 控制流分析认为某个分支永远不可达
  • 联合类型与自定义类型守卫不完整或条件互斥

别用 any 把上游模型问题盖住

  1. 为无信息初始值显式声明元素或泛型类型
  2. 修正类型守卫，使返回条件与声明谓词一致
  3. 使用可辨识联合表达状态，避免多个布尔值形成非法组合

保持 strict 模式，不用 any 压制错误；把 never 当作上游模型问题的信号，而不是需要强制断言的障碍。
