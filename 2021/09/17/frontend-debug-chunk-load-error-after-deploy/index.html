前端疑难排查：ChunkLoadError 排查：前端发布后懒加载资源 404

发表于2021-09-17|更新于2021-09-17|前端排障

线上问题最怕“改一点试试看”。更可靠的方式是先稳定复现，再沿数据、时序、网络或渲染链路逐层缩小范围。

常见症状

  1. 发布后部分在线用户点击路由出现白屏
  2. 控制台出现 ChunkLoadError 或动态 import 失败
  3. 刷新页面后问题暂时消失

高概率根因

  1. 旧 HTML 或运行中的旧应用引用了已经被删除的 hash 文件
  2. CDN 与 HTML 缓存策略不一致
  3. 多节点发布期间 HTML 和静态资源来自不同版本

定位步骤

  1. 记录失败 chunk URL、页面版本号和 service worker 状态
  2. 直接请求资源并检查 CDN、源站和缓存响应头
  3. 对照发布清单确认旧 hash 是否仍在静态目录

修复方案

  1. 静态资源使用内容 hash 和长期缓存，HTML 使用短缓存或 no-cache
  2. 保留至少一个回滚窗口的旧资源，不要发布即删除
  3. 捕获动态导入失败并提示用户安全刷新

如何防止再次发生

采用先上传资源、再切换 HTML 的发布顺序，并在监控中按版本聚合 chunk 加载失败率。

修复完成后还应补充最小回归用例，并把关键上下文写进错误日志。只有能够在下一次自动发现同类问题，排障工作才算真正闭环。
