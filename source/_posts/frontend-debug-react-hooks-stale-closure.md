线上问题最怕“改一点试试看”。更可靠的方式是先稳定复现，再沿数据、时序、网络或渲染链路逐层缩小范围。

## 常见症状

1. 定时器或事件监听器始终读到第一次渲染的状态
2. Effect 加入依赖后不断请求或循环更新
3. 开发环境中订阅、请求或日志看起来执行两次

## 高概率根因

1. 每次渲染都会创建新的闭包，旧回调保留旧值
2. Effect 同时读取并更新不稳定依赖
3. StrictMode 会额外执行 setup/cleanup 来暴露不安全副作用

## 定位步骤

1. 启用 eslint-plugin-react-hooks 并处理完整依赖提示
2. 记录每次渲染的依赖引用是否变化
3. 检查 Effect 是否真正用于同步外部系统

## 修复方案

1. 状态更新依赖旧值时使用函数式更新
2. 事件回调需要最新值时重构数据流或使用适当的 Effect Event/ref
3. 返回 cleanup 取消订阅、定时器和过期请求

## 如何防止再次发生

减少 Effect 数量，把派生数据留在渲染阶段；不要通过禁用 exhaustive-deps 维持偶然可用的代码。

修复完成后还应补充最小回归用例，并把关键上下文写进错误日志。只有能够在下一次自动发现同类问题，排障工作才算真正闭环。
